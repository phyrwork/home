# T0031 — Battery integration cleanup and local release gate

Status: Accepted

Depends on: T0030

## Objective

Delete every superseded path, consolidate tests and current documentation around
observable behavior, and prove the complete lean integration locally. Add no new
control behavior.

## Required source shape

Production is limited to:

```text
house_battery_control/
├── __init__.py
├── config.py
├── model.py
├── planner.py
├── solis.py
├── controller.py
├── sensor.py
└── manifest.json
```

There is one controller, planner and Solis writer/lock. No compatibility adapter,
generic transaction, reentrant lock, cleanup task or workflow framework remains.

Delete all absorbed Python modules and abstraction-specific tests, including
`const`, `contracts`, `coordinator`, `domain_constants`, `energy`, `ha_writer`,
`interval`, `load`, `octopus_windows`, `reserve_planner`, `runtime_inputs`,
`solis_actuator`, `solis_config`, `solis_policy`, `solis_reader`, `solis_state`,
`strategy`, and `write_contracts`. Delete tracked/generated bytecode.

## Delete obsolete HA surfaces

Delete:

- `deployment/files/scripts/house_battery.yaml`;
- `deployment/files/input_booleans/house_battery.yaml`;
- broad-watchdog tests/fixtures;
- every guard, static-enable and broad-safe-baseline reference; and
- obsolete protection from any `.rsync-filter`.

Preserve the cycle-duration input, fused Octopus sensors, compact commissioned
entity mapping, diagnostic registry identities and T0030 sentinel.

## Test consolidation

Keep behavior-focused config/model, planner, Solis, controller, sensor, setup and
sentinel tests. Delete tests whose subject is an absorbed class/module.

Verify every T0026 local-acceptance requirement, especially rate/DST/reserve
math, split midnight slots, timeout provenance, bounded starts, persistent stops,
minimum-SOC stop, event-during-write, fail-safe latch, shutdown and sentinel.

## Documentation

Update current requirements, architecture and commissioning documentation for:

- the single-writer event-driven architecture;
- best-effort starts and persistent stops;
- latched mode-only fail-safe, shutdown and sentinel;
- Feed-In Priority and unmanaged Peak Shaving/feed limit;
- UTC/local-midnight split schedules;
- native bounds and optimistic control-plane proof limits; and
- the remaining deployment/live/24-hour acceptance gate.

Update T0001, T0026 and the commissioning log. Mark T0022, T0024 and T0025
superseded rather than rewriting their historical evidence.

## Static audit

Prove by repository search:

- no import/config reference to deleted names;
- no guard helper, broad script or static-enable key;
- no runtime Peak Shaving/feed-limit dependency;
- only `solis.py` writes integration controls;
- the sentinel writes only Self-Use;
- no tracked bytecode; and
- final production code is materially smaller with no duplicate path.

Record before/after module and nonblank production-line counts in T0026. Counts
are evidence, not a target to game.

## Local release gate

Run and record:

1. all battery component tests;
2. all deployment tests;
3. the full repository test suite;
4. Python compile/import checks;
5. YAML/render checks; and
6. Ansible syntax validation if it does not require 1Password/vault access;
   otherwise record it as the first auth-dependent deployment gate.

No 1Password, SSH, browser, deployment or live Solis access belongs to this
task. T0026 stays incomplete until later live acceptance and 24-hour observation.

## Completion

- Final source shape and searches pass.
- Local release gate is green or an auth-only syntax step is explicitly deferred.
- Council approves the implementation against T0026.
- Commit from an isolated worktree; do not deploy or push.
